## MODIFIED Requirements

### Requirement: Размеченное событие может хранить ожидаемый результат
`CategorizedEvent` ОБЯЗАНА иметь поле `expected_result`, способное хранить текстовое описание ожидаемого результата по событию. Значение формируется LLM-шагом BP-3 (`ExpectedResultModule`) вместе с остальной разметкой, при штатном запуске через `run_bp3()`.

#### Scenario: LLM сформировала ожидаемый результат
- **WHEN** BP-3 категоризирует нормализованный объект, и LLM-шаг формирования ожидаемого результата вернул непустое значение для id этого объекта
- **THEN** сохранённое размеченное событие содержит `expected_result`, заполненный этим значением

#### Scenario: Значение ещё не сформировано
- **WHEN** LLM-шаг формирования ожидаемого результата не вернул запись (или вернул пустое значение) для id новости
- **THEN** поле `expected_result` сохранённого события остаётся пустым (`NULL`), и сохранение события не завершается ошибкой

#### Scenario: Существующее поведение других полей не затронуто
- **WHEN** событие сохраняется с обычным набором данных категоризации (приоритет, категория, тональность, комментарий, требуемое действие, отдел, срок, список задач)
- **THEN** все эти поля сохраняются как прежде, независимо от значения `expected_result`
