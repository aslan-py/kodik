# Admin User Seed Specification

## Purpose

Гарантирует, что после применения миграций в базе существует ровно один пользователь с ролью `admin`, достаточный для первого входа в `/admin` — без него включить кого-либо ещё в систему через саму админку невозможно.

## Requirements

### Requirement: Миграция создаёт пользователя-администратора по умолчанию
Применение миграций к базе данных SHALL гарантировать наличие пользователя `User` с `email='admin@admin.ru'`, `role='admin'`, `is_active=true` и паролем `Admin123`, захэшированным тем же алгоритмом (bcrypt), что и остальные пароли пользователей в системе.

#### Scenario: Применение миграций к пустой базе
- **WHEN** миграции применяются к базе, где таблица `user` пуста
- **THEN** в `user` появляется ровно одна строка с `email='admin@admin.ru'`, `role='admin'`, `is_active=true`
- **AND** пароль `Admin123` проходит проверку через тот же механизм верификации пароля, что используется при входе в `/admin` и в API

### Requirement: Повторное применение миграции не создаёт дублей
Если пользователь с `email='admin@admin.ru'` уже существует (в т.ч. заведён вручную ранее), повторное применение миграции SHALL NOT создавать вторую строку и SHALL NOT изменять существующую — включая её роль, пароль и статус активности.

#### Scenario: Миграция применяется к базе, где admin@admin.ru уже есть
- **WHEN** в `user` уже существует строка с `email='admin@admin.ru'` (заведена вручную, с любыми значениями остальных полей)
- **THEN** после применения миграции в `user` остаётся ровно одна строка с этим email
- **AND** значения полей существующей строки (включая `role` и `password_hash`) не меняются

### Requirement: Созданный администратор может войти в админку
Пользователь, созданный этой миграцией, SHALL проходить проверку входа в `/admin` (`role` в списке ролей, которым разрешён вход, и `is_active=true`) сразу после применения миграции, без дополнительных ручных действий.

#### Scenario: Вход в /admin сразу после миграции
- **WHEN** после применения миграций выполняется вход в `/admin` с логином `admin@admin.ru` и паролем `Admin123`
- **THEN** вход проходит успешно, без предварительного создания или изменения пользователей через API или другую админскую сессию
