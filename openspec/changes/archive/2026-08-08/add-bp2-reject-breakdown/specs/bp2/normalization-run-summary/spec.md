## Purpose

Сводка одного прогона нормализации BP-2: сколько снимков и строк обработано и по каким причинам строки были отклонены, чтобы оператор мог оценить прогон без ручного запроса к таблице `normalized_item`.

## ADDED Requirements

### Requirement: Сводка прогона включает разбивку отклонённых строк по причине
Сводка, возвращаемая по завершении прогона нормализации, SHALL включать количество отклонённых строк по каждой причине отсева, определённой на этапе разбора и фильтрации (до записи в БД): чёрный домен, стоп-слово, стоп-тема, ложное срабатывание, ошибка разбора.

#### Scenario: Есть отклонённые строки нескольких причин
- **WHEN** прогон нормализации отклоняет часть строк по чёрному домену и часть — по стоп-слову
- **THEN** сводка показывает отдельное количество для каждой из сработавших причин

#### Scenario: Отклонений нет
- **WHEN** прогон нормализации не отклонил ни одной строки по этим причинам
- **THEN** сводка показывает нулевые значения по каждой причине, а не отсутствие поля

### Requirement: Отсев по лимиту шума остаётся отдельным полем сводки
Количество строк, отклонённых постфактум-проверкой лимита шума (после того как строки уже записаны), SHALL оставаться отдельным полем сводки и не смешиваться со счётчиками причин, определяемых до записи в БД.

#### Scenario: И обычный отсев, и отсев по лимиту шума сработали в одном прогоне
- **WHEN** в одном прогоне часть строк отклонена по стоп-слову, а часть уже записанных строк позже отклонена проверкой лимита шума
- **THEN** сводка показывает оба вида отсева раздельно, не суммируя их в одно число
