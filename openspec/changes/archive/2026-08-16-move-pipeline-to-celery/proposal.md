## Why

Сейчас pipeline запускается внутри процесса, который нажал кнопку или вызвал CLI: долгий парсинг/LLM блокирует запрос, состояние прогона не сохраняется, расписание отсутствует, а подготовленный Celery app не регистрирует даже существующие задачи. Для эксплуатационного режима нужны независимые worker-процессы, управляемое расписание и единая история ручных и автоматических запусков.

## What Changes

- Зарегистрировать Celery-задачи всех семи этапов и собирать общий прогон в последовательный Celery canvas, сохраняя правило «ошибка этапа не отменяет следующие этапы».
- Направлять production-запуски из админки, API, Beat и CLI в очередь; прямой runner оставить внутренним исполнителем worker и явным диагностическим режимом.
- Добавить постоянные записи прогона и его этапов со статусами, task IDs, источником запуска, результатами, ошибками и временем выполнения; запретить параллельные прогоны pipeline.
- Настроить отдельные очереди для управляющих задач, ресурсоёмкого BP-1 и этапов BP-2—BP-7.
- Добавить singleton Celery Beat, который запускает весь pipeline по cron-расписанию. `.env` задаёт default cron/timezone/enabled, а админка и API могут установить или сбросить runtime override без перезапуска Beat.
- Добавить в экран пайплайна админки управление расписанием, сведения о следующем запуске и ссылки/статусы последних прогонов.
- Добавить API запуска одного этапа/всего pipeline, чтения истории и чтения/изменения расписания для фронта.
- Добавить общий Docker image и отдельные Compose-сервисы `api`, Celery workers, `celery-beat` и Flower; uvicorn не запускает worker или Beat внутри себя.
- Защитить Flower аутентификацией и добавить healthchecks, инструкции запуска и диагностики очередей.
- **BREAKING**: кнопки админки и production CLI больше не ждут завершения этапа, а сразу возвращают принятый `run_id`; результат отслеживается по истории прогона.

## Capabilities

### New Capabilities

- `core/celery-pipeline-orchestration`: очередь этапов, последовательный общий прогон, блокировка пересечений и постоянная история выполнения.
- `api/pipeline-operations`: HTTP-контракт запуска, наблюдения за прогонами и управления эффективным расписанием.

### Modified Capabilities

- `core/celery-infrastructure`: из заготовки с пустым Beat превратить Celery в готовую контейнерную инфраструктуру worker/Beat/Flower с маршрутами очередей и действующим расписанием.
- `admin/pipeline-control`: заменить синхронное выполнение кнопок на постановку в очередь и добавить управление расписанием/наблюдение за прогонами.

## Impact

Изменения затрагивают Celery app/tasks, runner-обвязку, новые модели и Alembic-миграцию, config/`.env`, API и админку, Dockerfile/Compose, тесты и эксплуатационную документацию. Требуются PostgreSQL и Redis; uvicorn, workers, Beat и Flower становятся отдельными процессами одного deployment. Бизнес-реализации BP-1—BP-7 и их порядок не переписываются.
