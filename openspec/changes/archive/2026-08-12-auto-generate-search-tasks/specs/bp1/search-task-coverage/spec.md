## Purpose

Поддержание полноты покрытия задачами сбора: каждая активная пара «источник + конкурент» имеет задачу сбора без ручного заведения, а ручные решения об исключении отдельных пар при этом сохраняются. Замыкает цепочку автоматического расширения источников — найденный агентом источник начинает участвовать в сборе сам.

## ADDED Requirements

### Requirement: Непокрытые пары получают задачу сбора автоматически
Перед началом сбора система SHALL создать задачу сбора для каждой пары активного источника и активного конкурента, для которой задачи сбора ещё не существует. Существующие задачи SHALL оставаться без изменений.

#### Scenario: В справочник добавлен новый источник
- **WHEN** в справочник источников добавлен активный источник, и запускается сбор
- **THEN** для этого источника создаются задачи сбора по каждому активному конкуренту, и сбор по ним выполняется в этом же прогоне

#### Scenario: В справочник добавлен новый конкурент
- **WHEN** в справочник конкурентов добавлен активный конкурент, и запускается сбор
- **THEN** для этого конкурента создаются задачи сбора по каждому активному источнику

#### Scenario: Источник добавлен автоматическим переносом кандидата
- **WHEN** источник попал в справочник переносом из очереди кандидатов, без участия человека
- **THEN** задачи сбора по нему появляются при ближайшем прогоне сбора, и участие человека для начала сбора по этому источнику не требуется

#### Scenario: Все пары уже покрыты
- **WHEN** запускается сбор, а задачи сбора существуют для всех активных пар
- **THEN** новые задачи не создаются, существующие не изменяются

### Requirement: Исключение пары выполняется деактивацией и переживает синхронизацию
Задача сбора, помеченная как неактивная, SHALL считаться существующей и SHALL NOT создаваться повторно. Автоматическое создание SHALL NOT изменять признак активности существующих задач.

#### Scenario: Пара исключена деактивацией задачи
- **WHEN** задача сбора деактивирована вручную, и запускается сбор
- **THEN** она остаётся деактивированной, дублирующая задача по этой паре не создаётся, и сбор по ней не выполняется

#### Scenario: Источник временно выключен
- **WHEN** источник помечен неактивным, и запускается сбор
- **THEN** задачи сбора по нему не создаются, а уже существующие остаются нетронутыми и снова начинают работать после включения источника

### Requirement: Автоматически создаются только задачи без поискового слова
Автоматически создаваемая задача сбора SHALL быть задачей без поискового слова — сплошным обходом источника. Наличие у пары задачи с поисковым словом SHALL NOT считаться покрытием этой пары.

#### Scenario: У пары есть только задача с поисковым словом
- **WHEN** для пары «источник + конкурент» заведена задача с поисковым словом, а задачи без него нет, и запускается сбор
- **THEN** дополнительно создаётся задача без поискового слова, а существующая задача с поисковым словом остаётся без изменений

### Requirement: Результат синхронизации виден в сводке прогона
Сводка прогона сбора SHALL сообщать, сколько задач сбора было создано автоматически в этом прогоне.

#### Scenario: Прогон, в котором добавились задачи
- **WHEN** прогон сбора создал новые задачи из-за появления источника или конкурента
- **THEN** в сводке прогона видно число созданных задач

### Requirement: Синхронизацию можно выполнить отдельно от сбора
Систему SHALL быть возможно попросить синхронизировать покрытие задачами, не запуская обход источников.

#### Scenario: Предварительный просмотр объёма
- **WHEN** запрошена синхронизация покрытия без сбора
- **THEN** недостающие задачи создаются, возвращается их число, и ни одного обращения к внешним источникам не выполняется
