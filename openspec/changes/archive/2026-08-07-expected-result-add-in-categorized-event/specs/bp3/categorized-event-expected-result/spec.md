## Purpose

Готовит в `categorized_event` место под ожидаемый результат события, чтобы в будущем его формировал LLM на этапе BP-3 вместе с остальной разметкой, а не отдельный агент на уровне BP-6.

## ADDED Requirements

### Requirement: Размеченное событие может хранить ожидаемый результат
`CategorizedEvent` ОБЯЗАНА иметь поле `expected_result`, способное хранить текстовое описание ожидаемого результата по событию.

#### Scenario: Значение ещё не сформировано
- **WHEN** событие сохраняется, а источника данных для ожидаемого результата на этапе BP-3 ещё нет
- **THEN** поле `expected_result` сохранённого события остаётся пустым (`NULL`), и сохранение события не завершается ошибкой

#### Scenario: Существующее поведение других полей не затронуто
- **WHEN** событие сохраняется с обычным набором данных категоризации (приоритет, категория, тональность, комментарий, требуемое действие, отдел, срок, список задач)
- **THEN** все эти поля сохраняются как прежде, независимо от значения `expected_result`

### Requirement: Поле expected_result в action_item не изменяется
Существующее поле `expected_result` в `ActionItem` ОБЯЗАНО продолжать работать без изменений — новое поле в `CategorizedEvent` существует отдельно и не влияет на текущее заполнение `ActionItem.expected_result`.

#### Scenario: Заполнение ActionItem работает как раньше
- **WHEN** `action_item` создаётся существующим механизмом (например, `ai_assistant.py`)
- **THEN** `ActionItem.expected_result` заполняется тем же способом, что и до этого изменения, независимо от значения `CategorizedEvent.expected_result`
