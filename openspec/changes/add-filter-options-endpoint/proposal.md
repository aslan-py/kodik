## Why

Фронтенду нужны значения для выпадающих фильтров витрины и плана действий, но сейчас их приходится угадывать, собирать из загруженных страниц или запрашивать через несколько несвязанных справочников. При этом часть значений хранится прямо в витрине, а для `assigned_user_id` и `department_id` фронту одновременно нужны машинный ID и читаемая подпись.

## What Changes

- Добавить один защищённый `GET /filter-options`, возвращающий две независимые секции: `showcase` и `action_items`.
- Для showcase возвращать уникальные непустые `category`, `region`, `competitor` и `department` из фактической витрины, а также полный упорядоченный набор отображаемых приоритетов.
- Для action-items возвращать статусы, сроки, приоритеты связанных событий, назначаемых пользователей и отделы в пределах данных, видимых текущей роли.
- Представлять `assigned_user_id` и `department_id` как варианты `{value, label}`, чтобы фронт показывал имя, но отправлял корректный числовой query-параметр.
- Возвращать даты в ISO-формате `YYYY-MM-DD`; локализованное отображение остаётся задачей фронтенда.
- Добавить в `GET /action-items` отсутствующие query-фильтры `deadline` и `priority`, чтобы все выданные варианты фильтров можно было применить.

## Capabilities

### New Capabilities

- `api/filter-options`: единый контракт получения доступных вариантов фильтров для showcase и action-items, включая ролевую область видимости.

### Modified Capabilities

Нет.

## Impact

Изменения затрагивают новый API router/schema/service/CRUD для вариантов фильтров, регистрацию маршрута, документацию OpenAPI и цепочку list-фильтра action-items. Добавляется одна HTTP-операция; после совместного применения change `verify-and-stabilize-api-endpoints` его manifest должен учитывать 91 операцию вместо 90. Схема БД и существующие URL не меняются.
