## Why

Ручной прогон показал, что Celery и этапы BP-1/BP-2 могут завершиться
технически успешно, хотя в витрину не попадает ни одной записи: BP-1 сохранил
`RawItem` с пустым `items`, а BP-2 честно нормализовал ноль элементов. Такое
состояние не даёт администратору понять, где именно оборвался поток данных, и
не подтверждает работоспособность всего конвейера.

## What Changes

- Ввести явный контракт передачи данных между BP-1 и BP-2: пустой результат
  сбора должен быть наблюдаемым исходом с причиной, а не неотличимым от
  содержательного сохранённого снимка.
- Исправить адаптивный сбор для совместимости с доверенными TLS-цепочками,
  используемыми источниками, без глобального отключения проверки сертификатов.
- Сделать результат BP-2 диагностируемым: отдельно показывать число полученных
  элементов, число созданных нормализованных строк и причины нулевого выхода.
- Добавить сквозную проверку переходов BP-1 → BP-2 → BP-3 → BP-4 → BP-5/BP-6
  на детерминированных данных и эксплуатационную проверку реального источника.
- Устранить расхождения JSON-контрактов, обнаруженные при проверке, сохранив
  обратную совместимость существующих `RawItem`.

## Capabilities

### New Capabilities

- `core/pipeline-data-contracts`: наблюдаемые контракты и результаты передачи
  данных между последовательными этапами конвейера.

### Modified Capabilities

- `bp1/adaptive-collection-run`: успешное сохранение результата сбора должно
  различать содержательный и пустой результат, а TLS-проверка должна работать
  для поддерживаемых доверенных центров сертификации.
- `bp2/normalization-run-summary`: сводка нормализации должна объяснять нулевой
  выход без необходимости читать исходный JSON вручную.
- `core/pipeline-stage-runner`: история прогона должна сохранять достаточный
  результат этапа, чтобы определить фактический переход данных между этапами.

## Impact

- `Dockerfile.backend`, хранилище доверенных сертификатов и сборка backend-образа.
- `src/bp1/adaptive/`, `src/bp1/storage.py`, JSON-схемы и тесты BP-1.
- `src/bp2/`, модели/сводки прогона, API и админская история конвейера при
  необходимости.
- Сквозные тесты этапов BP-1…BP-7 и эксплуатационная инструкция проверки.
