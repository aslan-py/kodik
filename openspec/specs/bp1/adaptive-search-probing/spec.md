# bp1/adaptive-search-probing Specification

## Purpose

Поиск рабочего адреса выдачи по источнику: система перебирает способы
обратиться к поиску сайта (query-параметры, HTML-форма, реформулировки
запроса), чтобы адаптивный сбор и регистрация источника могли получить
адрес страницы результатов, на которой действительно есть искомая
компания, вместо угадывания одного фиксированного параметра.

## Requirements

### Requirement: Перебор поиска доступен при регистрации источника и при сборе
Проверка поискового эндпоинта источника (при регистрации, флаг
«проверить поиск») и адаптивный сбор по конкуренту SHALL успешно
выполнять перебор вариантов поиска без отказа из-за внутренней ошибки
конфигурации перебора.

#### Scenario: Регистрация источника с проверкой поиска
- **WHEN** источник регистрируется с включённой проверкой поискового
  эндпоинта
- **THEN** перебор вариантов поиска выполняется и завершается результатом
  (найден рабочий вариант или ни один не подошёл), не завершаясь ошибкой
  инициализации перебора

#### Scenario: Адаптивный сбор по задаче с конкурентом
- **WHEN** запускается адаптивный сбор по источнику, для которого ещё нет
  подсказки о рабочем параметре поиска
- **THEN** система перебирает варианты поиска и использует первый, на
  котором найден искомый конкурент

### Requirement: Найденная HTML-форма поиска отправляется тем способом, который она требует
Если на странице источника обнаружена поисковая форма с методом
отправки POST, перебор SHALL отправить её как POST-запрос с полями
формы, а не повторно запросить GET по тому же адресу. Если транспорт для
POST-отправки недоступен, этот вариант перебора SHALL быть помечен как
пропущенный, а не выполнен как GET.

#### Scenario: Форма поиска требует POST
- **WHEN** словарные query-параметры не дали выдачи, а на странице
  найдена форма поиска с методом POST
- **THEN** перебор отправляет форму POST-запросом с её полями и проверяет
  результат на наличие искомой компании

#### Scenario: POST-транспорт не подключён
- **WHEN** найдена форма поиска с методом POST, а перебору не передан
  способ выполнить POST-запрос
- **THEN** этот вариант перебора помечается пропущенным по причине
  отсутствия транспорта, и перебор переходит к следующему варианту
  (реформулировкам), не выполняя GET по адресу формы

### Requirement: Проверка «похоже на выдачу» может быть заменена вызывающей стороной
Перебор SHALL использовать переданную вызывающей стороной проверку
«похож ли ответ на страницу результатов поиска», если она передана, и
проверку по умолчанию — если нет.

#### Scenario: Вызывающая сторона не передала свою проверку
- **WHEN** перебор запущен без указания способа проверять «похоже на
  выдачу»
- **THEN** используется проверка по умолчанию, и перебор работает как
  обычно

#### Scenario: Вызывающая сторона передала свою проверку
- **WHEN** перебор запущен с указанием способа проверять «похоже на
  выдачу» (например, для источника, у которого признак пустой выдачи
  нетипичный)
- **THEN** результат каждой попытки перебора оценивается переданной
  проверкой, а не проверкой по умолчанию
