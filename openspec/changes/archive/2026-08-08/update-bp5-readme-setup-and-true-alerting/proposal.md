## Why

`src/bp5/BP5_README.md` не объясняет, что должно быть заполнено, чтобы алертинг реально сработал (пустой `event_type`/`channel`/`user`/`routing_rule` — и уведомлений просто не будет, молча), и содержит раздел «Осознанно не реализовано», который **устарел и сейчас фактически неверен**: там написано «реальной отправки в Telegram/email нет — заглушка», хотя в `src/bp5/pipeline.py` она уже реализована через `core.mail`/`core.telegram`. README не описывает, как работает `TRUE_ALERTING` — а это прямо ведёт к риску: разработчик может решить, что при `TRUE_ALERTING=False` кнопка в админке ничего не отправляет, хотя на деле SMTP/Telegram Bot API вызываются всегда — просто на тестовый адрес из `.env`, а не на реального получателя. Заодно у `.env.example` комментарий к `TRUE_ALERTING` описывает старую (уже не действующую) семантику флага.

## What Changes

- В начале `BP5_README.md` уточняется, что ключевые слова `event_type` ищутся только в заголовке (`title`) события витрины, а не по всему тексту — сейчас это написано только в глубине файла.
- Добавляется краткий чек-лист «что должно быть заполнено, чтобы алертинг сработал»: `event_type` (иначе ничего не распознаётся), `channel`, `user.telegram_id`/`user.email`, `routing_rule` (иначе распознанному событию некому уйти) — с явным «если справочник пуст — уведомлений не будет, без ошибки».
- В разделе `user` добавляется способ узнать свой числовой `telegram_id` (для тестовой отправки) и предупреждение, что демо-данные сидера используют ЗАВЕДОМО ФЕЙКОВЫЕ `telegram_id` — их нельзя использовать при `TRUE_ALERTING=true`.
- **Исправляется устаревший раздел** «Осознанно не реализовано» / «Доставка»: реальная отправка email/telegram уже реализована (`core.mail`/`core.telegram`), `instant` не является заглушкой.
- Добавляется раздел про `TRUE_ALERTING`: что это переключатель ТОЛЬКО адресата (`false` → `TEST_EMAIL`/`TEST_TG` из `.env`, `true` → реальные `email`/`telegram_id` получателя), а не переключатель самой отправки — попытка реальной отправки происходит всегда при запуске через `run_bp5()` (в т.ч. по кнопке в админке); полностью отключить отправку (`deliver=False`) может только сидер демоданных, из админки — нет.
- Правится комментарий к `TRUE_ALERTING` в `.env.example` — сейчас он говорит про старую (не действующую) семантику флага.
- Чисто документационное изменение — код и поведение системы не меняются.
