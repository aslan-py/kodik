## Why

Вход в `/admin` (FastAdmin) требует пользователя `User` с ролью `admin` или `analyst` (`api/admin/users.py::UserAdmin.authenticate`). Ни один существующий сидер (`core/scripts/stages/dictionaries.py`, `simple_dictionaries.py`) не заводит пользователя с ролью `admin` — все демо/тестовые пользователи создаются с ролью по умолчанию `pending` (`src/bp5/models.py::User.role`). Из коробки войти в админку некому: первый администратор должен появиться в БД раньше, чем кто-либо сможет назначить роли через саму админку — курица и яйцо. Нужен один гарантированный пользователь-администратор, который заводится сам по себе при поднятии базы.

## What Changes

- Новая ревизия Alembic создаёт (идемпотентно, `ON CONFLICT (email) DO NOTHING`) одного пользователя-администратора: `full_name='Admin'`, `email='admin@admin.ru'`, `role='admin'`, `password_hash` — bcrypt-хэш пароля `Admin123` (через тот же `api/security.py::hash_password`, что и остальной логин), `department_id=NULL`, `telegram_id=NULL`, `is_active=true`.
- Пароль `Admin123` соответствует действующей политике (`api/validators/users.py::validate_password`: ≥8 символов, есть заглавная/строчная буква и цифра) — валидатор в самой миграции не применяется (это не self-service регистрация), но пароль ему удовлетворяет.
- Downgrade удаляет ровно эту строку по email.

## Capabilities

### New Capabilities
- `core/admin-user-seed`: гарантированное наличие ровно одного пользователя-администратора после применения миграций, без которого вход в `/admin` невозможен.

_нет_

## Impact

- Код: новая ревизия в `alembic/versions/` (down_revision — текущий head `d8be5a20d9b1`, миграция синхронизации `source_candidate.domain`).
- БД: одна новая строка в `user`. Существующие данные не затрагиваются — вставка идемпотентна по `email`.
- Не пересекается с `core/scripts/stages/dictionaries.py`/`simple_dictionaries.py`: те остаются источником демо/тестовых данных для пайплайна, этот пользователь — инфраструктурный (доступ в админку), заводится независимо от того, какой сценарий сидинга применяется.
- Секрет: пароль `Admin123` в открытом виде попадает в исходный код миграции (в git). Это осознанный компромисс для локальной/предпром среды, отмечен как риск в design.md — не для продакшена без смены пароля сразу после первого входа.
