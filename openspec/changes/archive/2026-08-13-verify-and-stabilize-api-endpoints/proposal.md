## Why

Код в `api/` активно меняется, но текущие 62 API-теста проверяют только security, CRUD и service-слой и ни разу не вызывают FastAPI через HTTP. Сейчас приложение публикует 90 операций; без контрактной проверки поломка регистрации роутера, dependency injection, ролевого доступа, сериализации ответа или HTTP-кода может остаться незамеченной.

## What Changes

- Зафиксировать полный автоматически проверяемый реестр HTTP-операций из OpenAPI, включая публичные страницы документации и mount админки.
- Добавить endpoint-тесты для всех 90 операций: доступ без токена, матрица ролей `pending`/`viewer`/`analyst`/`admin`, успешные ответы, валидация, `404` и конфликты там, где они предусмотрены контрактом.
- Выполнять HTTP-тесты через ASGI-приложение с изолированной транзакцией БД и моками только для внешних границ — почты и других сетевых отправок.
- Исправить обнаруженные тестами несоответствия в роутерах, зависимостях, схемах, сервисах или документации OpenAPI, сохраняя заявленную обратную совместимость API.
- Добавить общий smoke-контроль, запрещающий необработанные `5xx` для покрытых валидных и ошибочных сценариев.

## Capabilities

### New Capabilities

- `api/http-endpoint-contract`: контракт доступности, авторизации, валидации и ответов всех HTTP-эндпоинтов приложения.

### Modified Capabilities

Нет.

## Impact

Основные изменения ожидаются в `tests/api`, тестовых зависимостях и фикстурах. Если контрактные прогоны выявят реальные дефекты, точечные исправления могут затронуть `api/endpoints`, `api/dependencies.py`, `api/schemas`, `api/service`, `api/crud`, регистрацию роутеров и OpenAPI-описания. Схема БД и публичные URL не должны меняться без отдельного согласования.
