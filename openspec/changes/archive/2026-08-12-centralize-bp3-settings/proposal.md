## Why

BP-3 ходит во внешние платные сервисы — LLM для категоризации и поиск для подбора новых источников, — но параметры этих вызовов зашиты в код. Сколько источников запрашивать за раз, насколько глубоко искать, за какой период, с какой температурой и лимитом токенов обращаться к модели — всё это литералы в `src/bp3/modules/source_finder_module.py` и `src/bp3/config.py`. Именно эти значения определяют стоимость и качество прогона, и именно их хочется покрутить, не открывая исходники: расширить окно поиска, когда источников находится мало, или сузить объём, когда прогон стал дорогим.

Отдельно: адрес API вынесен в константу `API_BASE` с закомментированной рядом альтернативой (`openrouter.ai` против `api.kodikrouter.ru`) — то есть переключение между провайдерами уже происходит, но правкой кода и комментария.

Ещё одна деталь: глубина поиска (`search_depth`) принимает фиксированный набор значений, но передаётся сырой строкой. Опечатка в ней обнаружится только на ответе внешнего сервиса, тогда как во всех остальных местах проект использует перечисления (`core/enums.py`).

## What Changes

- **Параметры поиска источников переезжают в настройки** — число результатов на запрос, глубина поиска, временное окно; значения по умолчанию равны текущим (`2`, базовая глубина, неделя), поведение не меняется.
- **Параметры LLM-вызова переезжают в настройки** — температура и лимит токенов; адрес API становится настройкой вместо константы с закомментированной альтернативой.
- **Глубина поиска описывается перечислением** в `core/enums.py` по образцу остальных перечислений проекта, вместо сырой строки. Настройка типизируется этим перечислением, поэтому недопустимое значение отвергается при старте приложения, а не при обращении к внешнему сервису.
- **`.env` и `.env.example`** получают новый блок параметров BP-3 с пояснениями по каждому.

## Capabilities

### New Capabilities
_нет_

### Modified Capabilities
- `core/runtime-configuration`: под правило «эксплуатационные параметры задаются конфигурацией» подпадают и параметры обращения к внешним платным сервисам; настройка с фиксированным набором значений проверяется при старте приложения.

## Impact

- Код: `core/config.py` (новые поля), `core/enums.py` (новое перечисление), `src/bp3/config.py`, `src/bp3/modules/source_finder_module.py`.
- Конфигурация: новый блок переменных BP-3 в `.env` и `.env.example`; все со значениями по умолчанию, заполнять при обновлении ничего не требуется.
- Поведение: не меняется — значения по умолчанию равны текущим литералам.
- Стоимость прогона: не меняется по умолчанию, но становится управляемой без правки кода.
- Порядок: после `centralize-parsing-settings` — та задача задаёт структуру блоков `.env` и правило «одна переменная — одно поле `Settings`», в которое этот блок встраивается.
