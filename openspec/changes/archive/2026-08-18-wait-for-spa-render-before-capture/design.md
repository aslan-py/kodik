## Context

См. `proposal.md`. Ключевые ограничения, определяющие подход:

- `StealthStrategy` ([engines.py:83-157](src/bp1/adaptive/strategies/engines.py:83))
  трогать нельзя — используется для fedresurs.ru, менять сейчас
  запрещено явным решением пользователя по риску. Фикс обязан жить в
  НОВОМ классе, не в правке существующего.
- fedresurs.ru фактически не проходит через `AgenticOrchestrator`/эту
  деградационную лестницу вообще — у него отдельный контур
  (`src/bp1/collectors/fedresurs_rpa/`, свой `BrowserManager`). Значит
  маршрутизацию в лестнице деградации можно менять, не рискуя задеть
  fedresurs.ru технически — но `StealthStrategy` как класс всё равно не
  трогаем, это ограничение зафиксировано отдельно от вопроса риска для
  fedresurs.ru.
- `BrowserStrategy` ([orchestrator.py:313-426](src/bp1/adaptive/strategies/orchestrator.py:313))
  уже решает похожую проблему через `_wait_for_results_container`
  (селекторы) + `_wait_for_any_links` (порог `MIN_LINK_COUNT_FOR_CONTENT
  = 3` ссылок). Но для rbc.ru она ни разу не выполнялась (`has_captcha`
  исключает её из допустимых стратегий), поэтому нет оснований считать,
  что её селекторы подойдут. Хуже — `_wait_for_any_links` с порогом 3
  ссылки прошёл бы мгновенно на «оболочке» rbc.ru (369 ссылок нав/футер),
  ничего реально не дождавшись.
- `MIN_LINK_COUNT_FOR_CONTENT`/`_is_informative_html`
  ([orchestrator.py:33-66](src/bp1/adaptive/strategies/orchestrator.py:33))
  — общая, разделяемая константа/функция, используется и для решения
  «деградировать ли FAST/CRAWL4AI дальше». Её нельзя менять глобально —
  затронет не связанные с этим change решения о деградации.

## Goals / Non-Goals

**Goals:**

- Новая стратегия реально дожидается JS-отрисованного контента на
  антибот+SPA источниках (в первую очередь — подтверждено на примере
  rbc.ru), не просто формально копирует механизм `BrowserStrategy`.
- `StealthStrategy` и её поведение остаются полностью без изменений.
- Источники, для которых нынешнее поведение уже устраивает, не должны
  пострадать от рефакторинга маршрутизации.

**Non-Goals:**

- Не чиним `Crawl4AIStrategy` (тоже использует раннее событие рендеринга,
  `wait_until='domcontentloaded'`) — по решению пользователя, отдельный
  вопрос вне этого change.
- Не трогаем глобальный `MIN_LINK_COUNT_FOR_CONTENT`/`_is_informative_html`
  — они используются шире, чем эта стратегия.
- Не гарантируем, что `networkidle` решит проблему для АБСОЛЮТНО любого
  антибот-источника (сайты с постоянными фоновыми соединениями —
  аналитика, вебсокеты — могут никогда не давать networkidle) — для них
  остаётся деградация на WAYBACK/HITL, как и раньше.

## Decisions

### Новый класс стратегии, а не правка `StealthStrategy`

Копия `StealthStrategy` (переиспользует те же импорты —
`apply_stealth`/`bypass_qrator`/`get_context_config`/`get_launch_args` из
`src.bp1.collectors.stealth`) с одним отличием: между `page.goto(...)` и
`page.content()` добавлено ожидание. Дублирование ~50 строк — осознанный
компромисс: альтернатива (общая функция, параметризованная «ждать или
нет») означала бы правку тела `StealthStrategy.fetch()`, что запрещено.

### `networkidle` как основной сигнал ожидания

```python
try:
    await page.wait_for_load_state(
        'networkidle', timeout=_NETWORKIDLE_TIMEOUT_MS
    )
except Exception:
    pass  # не блокируемся бесконечно — читаем то, что есть (см. спеку)
html = await page.content()
```

`networkidle` — универсальный сигнал «JS доделал сетевую работу», не
завязанный на разметку конкретного сайта (в отличие от селекторов
`BrowserStrategy`, которые для rbc.ru не проверялись). Таймаут ожидания
— отдельный, меньший бюджет от общего `timeout_ms` стратегии (не блокирует
весь fetch, если networkidle не наступает).

Альтернатива (селекторы `BrowserStrategy` как основной сигнал) отвергнута:
непроверено на rbc.ru, требует поддержки списка селекторов под разные
сайты вручную.

### Локальный, более строгий порог ссылок как дополнительная подстраховка

После `networkidle` дополнительно проверяем число ссылок ЛОКАЛЬНЫМ
порогом (константа новой стратегии, не общий `MIN_LINK_COUNT_FOR_CONTENT`)
— если контент всё ещё выглядит как голая оболочка (мало ссылок сверх
типичного объёма навигации/футера), кратко опрашиваем страницу ещё
некоторое время (тот же паттерн, что `_wait_for_any_links`, но с другим
порогом), не блокируясь надолго. Это best-effort подстраховка на случай,
когда `networkidle` наступает раньше, чем реально нужный контент
отрисован (например, из-за фоновых aналитических соединений, которые
устаканиваются быстро, а результаты поиска — чуть позже).

Точное значение порога — эвристика, требует калибровки на реальном
прогоне (см. Risks). Не претендует на универсальность для всех сайтов.

### Новый `StrategyType` и маршрутизация

- `StrategyType.STEALTH_SPA` (условное имя, до реализации) добавляется в
  `schemas.py`.
- Регистрируется в `build_default_strategies()` наравне с остальными.
- `_ALLOWED_STRATEGIES_TABLE` (`has_captcha` → сейчас `(STEALTH, WAYBACK,
  HITL)`) переключается на `(STEALTH_SPA, WAYBACK, HITL)`.
- `_DEGRADATION_ORDER` — `STEALTH_SPA` заменяет `STEALTH` в общем порядке
  деградации (для источников без явного попадания в
  `_ALLOWED_STRATEGIES_TABLE`).
- `StrategyType.STEALTH` и `StealthStrategy` остаются зарегистрированными
  (не удаляются), но перестают быть тем, на что реально маршрутизирует
  классификация — доступны для явного использования
  (`start_with=StrategyType.STEALTH`), если понадобится в будущем.

## Risks / Trade-offs

- [Локальный порог ссылок — эвристика без калибровки под реальный
  трафик] → зафиксировать как best-effort, проверить на контролируемом
  прогоне rbc.ru × «Сбербанк» (аналог задачи 5.3 из
  `fix-search-probe-antibot-fetch`) перед тем как считать готовым.
- [`networkidle` может никогда не наступить на сайтах с постоянными
  соединениями] → таймаут ожидания ограничен отдельным бюджетом, при
  истечении просто читаем текущий контент, деградация на WAYBACK/HITL
  остаётся доступна как раньше.
- [Дублирование кода между `StealthStrategy` и новым классом] →
  осознанный компромисс ради изоляции риска для fedresurs.ru; если в
  будущем ограничение снимется, стратегии можно будет слить.
- [Расширение `StrategyType` — это добавление, не влияет на уже
  сохранённые данные/кэш (строковый enum, обратная совместимость
  сохраняется).]

## Migration Plan

1. Добавить новый `StrategyType`, класс стратегии, регистрацию — без
   изменения поведения для источников, у которых `has_captcha=False`.
2. Переключить маршрутизацию `has_captcha` на новую стратегию.
3. Контролируемая проверка на rbc.ru × «Сбербанк» — подтвердить, что
   реальный контент (со словом «Сбербанк») теперь захватывается.
4. При откате — вернуть `_ALLOWED_STRATEGIES_TABLE` на `STEALTH`; новый
   класс и `StrategyType` можно оставить зарегистрированными без вреда.
