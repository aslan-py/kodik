## Why

`src/bp3/README.md` уже перечисляет таблицы категорий и отделов, но не говорит, кто их заполняет — читатель может решить, что это, как справочники BP-2, нужно вручную наполнять аналитику. На деле `Category`/`Department` — закрытый список из ТЗ, который заводит разработчик на старте, и аналитику трогать его не нужно. Отдельно README не объясняет, что произойдёт при повторном запуске BP-3 (кнопка нажата второй раз) — окажется ли это тратой токенов на уже обработанные новости или нет; на деле это уже определяется механикой `fetch_data()` (только `status=ok` и без строки в `categorized_event`), но нигде не описано.

## What Changes

- В `src/bp3/README.md`, у раздела про категории и отделы, явно указывается: это закрытый список, разработчик заполняет его на старте (при разворачивании), аналитик добавлять/менять записи сам не должен.
- Добавляется раздел, описывающий, что происходит при повторном запуске BP-3: LLM обрабатывает только `normalized_item` со `status=ok`, у которых ещё нет строки в `categorized_event` — уже обработанные новости повторно не гонятся через LLM (токены не тратятся), дублей в `categorized_event` не создаётся.
- Чисто документационное изменение — код и поведение системы не меняются.
