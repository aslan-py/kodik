# core/runtime-configuration Specification

## Purpose

Параметры, влияющие на работу системы в конкретном развёртывании — объёмы и глубина сбора, сетевые ограничения, время жизни кэшей, режимы прогона, — задаются конфигурацией окружения, а не значениями в исходном коде, и читаются приложением единственным способом.

## Requirements

### Requirement: Эксплуатационные параметры настраиваются без правки кода
Параметры, которые меняются при эксплуатации под конкретное развёртывание или поведение внешних источников — объём и глубина сбора, таймауты, степень параллельности, время жизни кэшей, режим прогона сбора, — SHALL задаваться конфигурацией окружения. Изменение такого параметра SHALL NOT требовать правки исходного кода или пересборки приложения.

#### Scenario: Изменение эксплуатационного параметра
- **WHEN** требуется изменить объём собираемого, таймаут обращения к источнику, степень параллельности или время жизни кэша
- **THEN** это достигается изменением конфигурации окружения и перезапуском приложения, без правки исходного кода

#### Scenario: Параметр не задан в конфигурации
- **WHEN** приложение запускается, а эксплуатационный параметр в конфигурации не задан
- **THEN** применяется значение по умолчанию, и приложение запускается штатно — обязательными являются только доступы к внешним системам, но не параметры поведения

### Requirement: Единственный способ чтения конфигурации
Приложение SHALL читать переменные окружения только через общий объект настроек. Модуль SHALL NOT читать переменные окружения напрямую и SHALL NOT реализовывать собственный разбор файла конфигурации.

#### Scenario: Модулю нужно значение из окружения
- **WHEN** модуль приложения использует значение, заданное переменной окружения
- **THEN** он получает его из общего объекта настроек, а не собственным чтением окружения или файла конфигурации

#### Scenario: Обязательный доступ не заполнен
- **WHEN** приложение запускается, а обязательная переменная окружения (доступ к внешней системе) не заполнена
- **THEN** запуск завершается ошибкой с указанием недостающей переменной, вместо запуска с пустым значением

### Requirement: Пример конфигурации отражает обязательность переменных
Файл-образец конфигурации SHALL содержать все переменные, которые читает приложение, и по каждой SHALL показывать, обязательна ли она: обязательные — без значения и с пометкой, необязательные — со значением по умолчанию. Переменные, которые приложение не читает (нужные только средствам развёртывания), SHALL быть отделены явным образом.

#### Scenario: Развёртывание с нуля по образцу
- **WHEN** новое окружение настраивается копированием файла-образца
- **THEN** из него видно, какие переменные обязательно заполнить перед запуском, а какие можно оставить со значениями по умолчанию

#### Scenario: В приложение добавлена новая настройка
- **WHEN** в общий объект настроек добавляется новое поле
- **THEN** соответствующая переменная появляется в файле-образце с пояснением назначения
