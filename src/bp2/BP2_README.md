# BP-2: Нормализация и фильтрация событий

BP-2 берёт сырые снимки из `raw_item` и превращает их в чистые факты в `normalized_item`.
Управляется через четыре справочника — их заполняет аналитик без изменения кода.

---

## Справочники

### `region` — регионы
Предзаполнен из `core/scripts/scripts_data/cities.json` при первом `seed_all`.
Редактировать вручную почти не нужно —
только если парсер присылает написание региона, которое не распознаётся.

| Поле | Тип | Описание |
|------|-----|---------|
| `name_display` | string | Каноническое название для витрины: `Волгоград` |
| `name_aliases` | string[] | Варианты написания в нижнем регистре: `["волгоград", "г. волгоград", "г волгоград"]` |
| `macro_region` | string | Федеральный округ: `ЦФО`, `ЮФО` — для карты рынка |
| `latitude` | float | Широта центра (WGS-84) |
| `longitude` | float | Долгота центра (WGS-84) |

**Когда добавлять:** если событие приходит с регионом, которого нет в справочнике, `region_id` будет `NULL`.
Добавьте строку и пропишите все варианты написания в `name_aliases`.

---

### `black_domain` — чёрный список доменов
Сайты-публикаторы, контент которых отсеивается целиком — заказные материалы, компромат.
Проверяется по домену URL события (`media_domain`).

| Поле | Тип | Описание |
|------|-----|---------|
| `domain` | string | Домен без схемы и пути: `kompromat.ru`, `critics24.com` |
| `reason` | string | Пояснение: `Заказной ресурс`, `Компрометирующие публикации` |
| `is_active` | bool | `true` — домен активен; `false` — временно отключён без удаления |

**Пример:** `critics24.com` | `Заказные публикации против конкурентов` | `true`

---

### `stop_word` — стоп-слова и стоп-темы
Фраза проверяется вхождением подстроки в `title` + `text` события (без учёта регистра).
Одна запись = одна фраза. Тип определяет причину отсева.

| Поле | Тип | Описание |
|------|-----|---------|
| `phrase` | string | Слово, корень или фраза целиком: `реклама`, `наруш`, `бегемот в зоопарке` |
| `type` | enum | `stop_word` — нерелевантный контент; `stop_topic` — тема-шум; `false_positive` — ложное срабатывание по конкуренту |
| `note` | string | Пояснение для аналитика: почему добавили |
| `is_active` | bool | `true` — правило активно |

**Типы подробнее:**
- `stop_word` — нежелательный контент: `реклама`, `акция`, `промокод`
- `stop_topic` — тема не про конкурента: `гороскоп`, `погода`, `курс валют`
- `false_positive` — конкурент упоминается, но не по теме: `бегемот в зоопарке` (компания «Бегемот» vs животное)

**Как вводить:** одно слово или корень на запись. Корень ловит все словоформы (`наруш` → нарушение/нарушений/нарушениях). Запятые и несколько слов через запятую **не работают** — это будет одна длинная фраза.

---

### `topic_limit` — антишум
Ограничивает количество событий от одной группы (конкурент/источник/СМИ/регион) за период.
Самые свежие события остаются, лишние старые становятся `rejected(noise_limit)`.

| Поле | Тип | Описание |
|------|-----|---------|
| `scope` | enum | По какой группе считать: `competitor`, `source`, `media`, `region` |
| `max_count` | int | Максимум событий на одну группу за окно. Сверх — отсев |
| `window` | enum | `run` — только этот прогон; `day` — последние 24 ч; `week` — последние 7 дней |
| `note` | string | Пояснение: `СКС занимает ~40% отчёта несколько недель подряд` |
| `is_active` | bool | `true` — правило активно |

**Примеры правил:**

| scope | max_count | window | Смысл |
|-------|-----------|--------|-------|
| `competitor` | 10 | `week` | Один конкурент — не больше 10 событий в неделю |
| `media` | 5 | `day` | Один сайт-публикатор — не больше 5 событий в сутки |
| `region` | 2 | `run` | Один регион — не больше 2 событий за прогон |

## Выходная таблица `normalized_item`

Результат BP-2. Одно событие из `raw_data.items[]` — одна строка.
`status=ok` → передаётся в BP-3. `status=rejected` → хранится для разбора аналитиком, не удаляется.

| Поле | Тип | Описание |
|------|-----|---------|
| `id` | int | Первичный ключ |
| `raw_item_id` | int | Ссылка на исходный снимок `raw_item` |
| `competitor_id` | int | Конкурент (из справочника). `NULL` если не распознан |
| `region_id` | int | Регион (из справочника). `NULL` если не распознан |
| `source_id` | int | Источник (Яндекс.Новости и т.д.) |
| `published_at` | date | Дата публикации события (из сырой строки) |
| `title` | string | Заголовок события |
| `media_name` | string | Название СМИ-публикатора |
| `media_domain` | string | Домен публикатора (для проверки black_domain) |
| `url` | string | Ссылка на событие |
| `text` | string | Тело события (вход для стоп-слов и промпта LLM в BP-3) |
| `extra` | json | Источник-специфичные поля (зарплата, категория и т.д.) |
| `dedup_key` | string | SHA-256 хэш `competitor\|norm(title)\|published_at\|region`. `UNIQUE` — дедупликация через `ON CONFLICT` |
| `status` | enum | `ok` — в работу; `rejected` — отсеяно |
| `reject_reason` | enum | Причина отсева: `black_domain`, `stop_word`, `stop_topic`, `false_positive`, `noise_limit`, `parse_error` |
| `created_at` | datetime | Время нормализации |
