# bp6/action-item-generation Specification

## Purpose

Автоматически переносит задачи, сформированные LLM на этапе категоризации (BP-3), в план действий (`action_item`) для приоритетных событий — чтобы отделам не приходилось вручную заводить задачи по каждому значимому событию.

## Requirements

### Requirement: Задачи переносятся только для приоритетных событий
Автогенерация ОБЯЗАНА рассматривать только события витрины с приоритетом П1 или П2. События с приоритетом П3/П4 не порождают автоматических задач.

#### Scenario: Событие с приоритетом П1
- **WHEN** событие витрины имеет приоритет П1 и связанное размеченное событие содержит непустой список задач
- **THEN** для каждой задачи из списка создаётся строка `action_item`

#### Scenario: Событие с приоритетом П3
- **WHEN** событие витрины имеет приоритет П3 (или П4), даже если у связанного размеченного события есть список задач
- **THEN** ни одна строка `action_item` для этого события не создаётся

### Requirement: Одна задача — одна строка action_item
Каждый элемент списка задач размеченного события (`categorized_event.task`) ОБЯЗАН порождать отдельную строку `action_item`, а не объединяться в одну запись.

#### Scenario: У события несколько задач
- **WHEN** размеченное событие с приоритетом П1/П2 содержит список из нескольких задач
- **THEN** создаётся ровно столько строк `action_item`, сколько задач в списке, каждая с текстом ровно одной задачи

### Requirement: Автозаведённая задача назначается на отдел, не на человека
Автоматически созданная строка `action_item` ОБЯЗАНА иметь заполненный `department_id` (тот же отдел, что определён при категоризации на BP-3) и пустой (`NULL`) `assigned_user_id`.

#### Scenario: Создание автозадачи
- **WHEN** автогенерация создаёт строку `action_item` по задаче из размеченного события
- **THEN** `department_id` заполнен отделом из категоризации, `assigned_user_id` остаётся `NULL` — конкретного исполнителя назначает человек позже

### Requirement: Событие обрабатывается один раз
Автогенерация ОБЯЗАНА обрабатывать каждое подходящее событие витрины не более одного раза. Последующие изменения списка задач у уже обработанного события (например, из-за переразметки) НЕ ОБЯЗАНЫ порождать новые или изменять существующие строки `action_item`.

#### Scenario: Повторный прогон после того, как событие уже обработано
- **WHEN** запускается автогенерация, а событие витрины уже было обработано раньше (для него уже создавались строки `action_item`)
- **THEN** повторных строк `action_item` для этого события не создаётся, уже существующие строки не изменяются и не удаляются

#### Scenario: Новое подходящее событие в том же прогоне
- **WHEN** в витрине появилось новое (ещё не обработанное) событие с приоритетом П1/П2 и непустым списком задач
- **THEN** оно обрабатывается в этом прогоне независимо от того, что другие события уже были обработаны ранее
