## 5. Проверка

- [x] 5.1 Прогнать целевые тесты (`tests/bp1/adaptive/`) и `ruff check`.
- [x] 5.2 Запросить у пользователя полный `pytest` и разобрать лог при
      падениях. (462 passed, падений нет.)
- [x] 5.3 Контролируемая проверка на реальной паре rbc.ru × «Сбербанк».
      Подтверждено: эскалация транспорта реально работает — `SearchUrlProber`
      дошёл до STEALTH и получил контент (~350 КБ) и для `q=`, и для
      `query=` (раньше пробер не получал контент вообще ни на один
      параметр). Обнаружена ОТДЕЛЬНАЯ проблема вне рамок этого change:
      причинная проверка `_looks_unfiltered` (Жаккар по множеству URL
      карточек, порог 0.7) отвергла оба кандидата как «совпадающие с
      базовой лентой» — на реальной странице rbc.ru много сквозных ссылок
      (навигация/сайдбар/футер), которые перевешивают немногочисленные
      реальные ссылки на карточки результата, из-за чего честно
      отфильтрованный `query=` тоже даёт высокое совпадение с базой.
      `design.md` этого change явно относил `_looks_unfiltered` к
      non-goals как «уже корректный» — предположение не подтвердилось на
      реальном контентном сайте. Решено (см. диалог с пользователем):
      завершить и заархивировать этот change как есть (эскалация
      транспорта — самостоятельная, подтверждённая ценность), находку по
      причинной проверке оформить отдельным change.
