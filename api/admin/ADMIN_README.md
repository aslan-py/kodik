# Админка (FastAdmin)

Веб-интерфейс над всеми таблицами проекта: справочники конвейера правятся
руками, слои данных доступны на просмотр. Закрывает требование ТЗ
«добавление конкурента или источника не требует доработки кода» (BP-7).

---

## Нужен ли отдельный сервер или контейнер?

**Нет.** Это то же самое приложение, что и API: FastAdmin монтируется
саб-приложением в `api/main.py` (`app.mount('/admin', admin_app)`). Отдельного
процесса, порта, `docker-compose`-сервиса и сборки фронтенда не требуется:

- **сервер** — тот же `uvicorn api.main:app`, который поднимает API;
- **порт** — тот же `8000`, админка живёт на пути `/admin`;
- **фронтенд** — React+antd уже собран внутри пакета `fastadmin`, Node и
  `npm build` не нужны;
- **контейнер** — не нужен. В `docker-compose.yml` лежит только
  инфраструктура (postgres, redis, pgadmin, redis-commander), само приложение
  запускается локально — админка ничего в этом не меняет.

## Запуск

```bash
# 1. Инфраструктура (если ещё не поднята)
docker-compose up -d

# 2. Зависимости — здесь ставится и сам fastadmin
pip install -r requirements.txt

# 3. Миграции (специально для админки миграций нет — схема БД не менялась)
alembic upgrade head

# 4. Тот же сервер, что и для API
uvicorn api.main:app --reload
```

Открыть: **http://localhost:8000/admin**

Рядом, в том же процессе: Swagger — http://localhost:8000/docs

## Вход

Логин — **email**, пароль — тот же, что и для API. Пускает роли **`admin`** и
**`analyst`** (`viewer` и `pending` получают отказ).

Если админа ещё нет, роль поднимается руками — отдельного эндпоинта для этого
намеренно нет (см. `api/API_README.md`):

```bash
# зарегистрировать пользователя обычным способом
curl -X POST http://localhost:8000/auth/register \
  -H "Content-Type: application/json" \
  -d '{"email":"me@example.com","password":"MyPassword123!"}'
```

```sql
-- выдать ему права (psql / pgAdmin на localhost:5050)
UPDATE "user" SET role = 'admin' WHERE email = 'me@example.com';
```

## Настройки (`.env`)

| Переменная | Значение по умолчанию | Зачем |
|---|---|---|
| `ADMIN_SITE_NAME` | `Кодик — админка` | Заголовок на странице входа и в шапке |
| `ADMIN_LANGUAGE` | `ru` | Язык интерфейса |
| `ADMIN_SECRET_KEY` | пусто → берётся `JWT_SECRET_KEY` | Подпись сессии админки |
| `ADMIN_SESSION_COOKIE_SECURE` | `False` | **Обязательно `False` для локального `http://`** |

Про `ADMIN_SESSION_COOKIE_SECURE`: в самой библиотеке по умолчанию `True`, и
тогда кука сессии уходит только по HTTPS — на `http://localhost` вход молча
не срабатывает (форма принимает пароль и возвращает обратно). Для прода за
TLS верните `True`.

Значения раскладываются в `os.environ` из `core/config.py` в
`api/admin/__init__.py` — до импорта пакета, потому что FastAdmin читает свои
настройки обычным `os.getenv` в момент импорта, а наш `.env` разбирает
pydantic-settings и в окружение ничего не пишет.

## Что где лежит в меню

Разделы намеренно повторяют группировку тегов Swagger — админка и
документация API читаются одинаково.

| Раздел | Таблицы | Режим |
|---|---|---|
| **Пользователи** | `user` | CRUD, **только для `admin`** |
| **Витрина** | `showcase_event` | только просмотр |
| **План действий** | `action_item` | CRUD |
| **Администрирование · Парсинг** | `competitor`, `source`, `trigger`, `search_task` | CRUD |
| **Администрирование · Нормализация** | `region`, `black_domain`, `stop_word`, `topic_limit`, `category`, `department` | CRUD |
| **Администрирование · Алертинг** | `event_type`, `channel`, `routing_rule` | CRUD |
| **Данные конвейера** | `raw_item`, `normalized_item`, `categorized_event`, `alert`, `source_candidate` | только просмотр |

FastAdmin поддерживает один уровень вложенности меню, поэтому иерархия
«Администрирование → подраздел» изображена префиксом в названии раздела.

## Связанные таблицы: два пути заполнения

`search_task` — это связка «конкурент × источник × триггер», то есть перед
ней нужно завести три справочника. Сделано с двух сторон:

1. **Из карточки справочника (инлайн).** Открываете конкурента — внизу
   таблица его задач сбора, добавляете строку не уходя со страницы. То же на
   странице источника и триггера. Аналогично `event_type` → правила
   маршрутизации.
2. **Отдельным списком.** `search_task` есть самостоятельным пунктом меню:
   конкурент, источник и триггер выбираются из выпадающих списков, которые
   подтягивают уже заведённые записи и показывают их человеческие названия
   (за это отвечает `__str__` у моделей).

Чего в интерфейсе нет: кнопки «создать конкурента прямо из формы задачи» —
у выпадающего списка FastAdmin такой возможности не предусмотрено. Поэтому
новый конкурент заводится либо в своём разделе, либо сразу вместе с задачами
через инлайн (путь 1).

## Правила доступа

- **Удаление отключено везде.** Все внешние ключи объявлены с
  `ondelete='RESTRICT'`, а конвенция проекта — мягкое выключение: снимите
  галочку `is_active`, строка останется в истории. Физический `DELETE` всё
  равно упирался бы в ошибку БД на первой же ссылке.
- **Витрина и слои конвейера — только чтение.** Их пишет сам конвейер.
  Отдельно про витрину: прямая правка `showcase_event` разъехалась бы с
  `categorized_event` и была бы затёрта следующим прогоном BP-4, поэтому
  разметка правится через `PATCH /showcase/{id}` — там write-through сделан
  один раз (`api/crud/showcase.py`).
- **Таблицу `user` правит только `admin`.** Иначе `analyst` мог бы выдать
  себе роль `admin` прямо из админки.
- `region` — без `is_active`: статический справочник городов, выключать в нём
  нечего.

## Как проверить, что всё поднялось

1. `http://localhost:8000/admin` — страница входа с заголовком «Кодик».
2. Вход под `admin` — видны все семь разделов меню.
3. «Администрирование · Парсинг» → «Конкуренты» → создать запись → открыть её
   → внизу инлайн «Задачи сбора».
4. «Данные конвейера» → «Сырьё парсинга»: список открывается, кнопок
   добавления и сохранения нет.
5. `http://localhost:8000/docs` — API продолжает работать как раньше.

## Структура кода

```
api/admin/
  __init__.py        # настройка ADMIN_* и импорт модулей (порядок важен)
  base.py            # базовые классы: сессия, права, разделы меню
  users.py           # вход в админку + таблица пользователей
  parsing.py         # BP-1: конкуренты, источники, триггеры, задачи сбора
  normalization.py   # BP-2/BP-3: регионы, фильтры, категории, отделы
  alerting.py        # BP-5: типы событий, каналы, правила маршрутизации
  workflow.py        # витрина (просмотр) и план действий (CRUD)
  pipeline.py        # слои данных конвейера — только просмотр
```

Модели админка берёт из `src/bpN/models.py` — своих таблиц не заводит.
`relationship()` и `__str__` в моделях добавлены как раз для неё: FastAdmin
показывает внешний ключ только при наличии `relationship`, а `__str__` — это
подпись записи в списках и выпадающих списках. На схему БД это не влияет,
миграции не требовались.
