## Context

См. proposal.md — Why. Здесь только выбор способа сравнения путей.

`_save_html()` (адаптивный парсер) и `copy_html_file()` (общий сервис персистентности, используется и классическим BP-1, и адаптивным) сегодня всегда вызываются последовательно на одном и том же результате: `parser_file_path` приходит из `item['extra']['file_path']`, которое для адаптивного парсера всегда уже указывает внутрь `settings.bp1_html_dir`. Для классических RPA-адаптеров (`fedresurs_rpa`, `kad_arbitr_rpa`) `file_path` указывает во временную папку парсера — там `copy_html_file` действительно копирует, а не дублирует путь. Проверка на совпадение путей должна работать корректно в обоих случаях, ничего не ломая для RPA-адаптеров.

## Goals / Non-Goals

**Goals:**
- Копирование файла на себя не обнуляет его содержимое ни при каких условиях гонки/блокировки.
- Поведение для RPA-адаптеров (реальное копирование из временной папки) не меняется.

**Non-Goals:**
- Не переписываем `_save_html()` и не меняем, куда адаптивный парсер кладёт файл изначально.
- Не восстанавливаем уже потерянные снимки.

## Decisions

**Сравнение путей — через `Path(...).resolve()`, а не `os.path.samefile()`.** `samefile()` требует, чтобы ОБА файла существовали на момент проверки и физически откроются (сравнивает inode/file-index) — в целевой ситуации файл только что создан `_save_html()` и должен существовать, так что `samefile()` формально сработал бы. Но именно `samefile()`-подобная проверка — то, что `shutil.copy2` уже пытается сделать внутри себя и делает это ненадёжно на Windows (см. proposal.md — падает `PermissionError` вместо `SameFileError`). Полагаться на тот же класс проверки, что уже подвела, неверно. `Path.resolve()` — чисто строковое/лексическое сравнение абсолютных путей без обращения к файловой системе, не подвержено блокировкам файла и антивирусным сканерам. Проверяется ДО первой попытки `shutil.copy2`, так что до самого ненадёжного кода дело не доходит вовсе.

**Проверка добавляется в начало функции, а не в обработчик исключения.** Сегодняшний код полагается на то, что `shutil.SameFileError` будет поймано ПОСЛЕ попытки копирования. Правильный порядок — проверить совпадение ДО попытки: тогда поведение не зависит от того, как конкретная ОС/файловая система сообщает о самокопировании.

## Risks / Trade-offs

- [Риск] **`Path.resolve()` на Windows не различает регистр** (`C:\A.html` и `c:\a.html` резолвятся в разные строки, хотя это один файл на файловой системе, нечувствительной к регистру). Для этой задачи не критично: оба пути (`parser_file_path` и `dest_path`) строятся из одних и тех же данных (`os.path.basename` + один и тот же `dest_dir`), поэтому регистр всегда совпадает при совпадении путей и никогда не совпадает при разных файлах.
