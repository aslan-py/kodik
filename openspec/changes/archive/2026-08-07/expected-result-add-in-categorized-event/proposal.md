## Why

`action_item.expected_result` сейчас заполняется отдельным вызовом LLM (`src/bp5/ai_assistant.py`, DeepSeek) уже на уровне BP-6 — по словам автора, это временная личная заглушка, не целевая архитектура. Цель — со временем сделать так, чтобы `expected_result` формировался один раз на этапе BP-3 (вместе с остальной разметкой события) и просто копировался в `action_item`, а не пересчитывался отдельным агентом для каждой задачи. Это первый шаг: подготовить место для значения в `categorized_event`.

**Важная оговорка (реальность переноса):** в BP-3 сейчас нет ни одного LLM-модуля, который бы генерировал `expected_result` — в отличие от `task` (см. изменение `auto-generate-action-items-from-llm`), где готовый `GenerationTaskModule` уже существовал и требовалось только сохранить его вывод. Здесь производителя данных пока нет вовсе, поэтому новая колонка первое время будет оставаться `NULL` у всех событий. Генерация (новый LLM-модуль в BP-3) и сам перенос значения в `action_item` — это отдельная будущая работа, не часть этого изменения.

## What Changes

- В `CategorizedEvent` (`src/bp3/models.py`) добавляется новое поле `expected_result` — ожидаемый результат по событию (`Text`, nullable). Источника данных для него в BP-3 пока нет, поле будет `NULL` до появления LLM-модуля, который его заполнит (будущая работа).
- Alembic-миграция на добавление колонки `expected_result` в `categorized_event`.
- `action_item.expected_result` **не убирается** и не меняется — обе колонки существуют параллельно. Перенос значения из `categorized_event` в `action_item` (замена вызова DeepSeek в `ai_assistant.py`) — вне рамок этого изменения.

## Non-goals (сознательно вне этого изменения)

- Никакого нового LLM-модуля в BP-3 для генерации `expected_result` — это следующий шаг, отдельное изменение, требующее координации с разработчиком BP-3.
- Никакого переноса/копирования значения в `action_item` и никаких правок `src/bp5/ai_assistant.py` — это тоже следующий шаг, после того как в `categorized_event.expected_result` появится реальный источник данных.
- Колонка `action_item.expected_result` не удаляется и не меняется.

## Capabilities

### New Capabilities
- `bp3/categorized-event-expected-result`: `categorized_event` получает поле под ожидаемый результат события, подготовленное для будущего заполнения LLM на этапе BP-3.

### Modified Capabilities
(нет)

## Impact

- **Модель:** `src/bp3/models.py` (`CategorizedEvent`) — новая колонка `expected_result`.
- **Миграция:** новая Alembic-ревизия в `alembic/versions/`.
- **Код BP-3 (`SaveResultsModule` и т.д.):** без изменений — колонка nullable без значения по умолчанию, ничего передавать не нужно, поле само останется `NULL`.
- **`action_item`:** без изменений (колонка `expected_result` там уже есть и продолжает жить своей жизнью, заполняясь через `ai_assistant.py`, пока эта заглушка не заменена).
